# Changelog

All notable changes to goSSMS are documented in this file. Format loosely
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); detailed
entries start with v0.0.2 onward.

## [0.0.8] - 2026-08-25

### Added

- **Permission awareness, end to end** — goSSMS as a login that is not
  `sysadmin`, built in five phases against two real non-admin logins on two
  instances. `README.md` § Required rights is the user-facing half.
  - **P0 — connect at all.** `gosmo.Server.loadInfo` read fifteen values in
    one statement, thirteen public and two from `sys.dm_os_sys_info`, so the
    DMV's permission check failed the whole SELECT and `Connect` failed with
    it: a `db_owner` could not open a connection. The statement is split, only
    the first half fatal, and the second sets `ServerInfo.SysInfoUnavailable`.
    `withAllMessages` (gosmo) rewrites a refused statement's error to carry
    every message of severity 11 and up, because `database/sql` hands back only
    the last one — Msg 5069 "ALTER DATABASE statement failed" without the Msg
    5011 that says why.
  - **P1 — the capability probe.** `gosmo/capabilities.go` plus
    `internal/db/capabilities.go`: one round trip at Connect asking
    `HAS_PERMS_BY_NAME` what this login may do, cached on `ServerConn`, with a
    lazy per-database probe on first touch. `HAS_PERMS_BY_NAME` has three
    answers, not two — `NULL` means the instance does not define that
    permission name, so `CapabilityState` keeps "granted", "denied" and
    "unknown" apart, and `Has`/`Allows` are the two questions that need them:
    "known granted, so offer this" and "not known denied, so don't withhold
    this".
  - **P2 — the read paths stop lying** (`permission_display.go`). A value the
    login could not read renders as `N/A`, never `0` and never a total taken
    over the rows it happens to see; a page whose main reads succeed opens with
    the refused row blank rather than failing; a grid built from a
    visibility-filtered catalog view says so at the top. One rule decides every
    placeholder and it is the fail-open one: blank a value only when the server
    actually answered "no" (`!Allows`, never `!Has`), so an unprobed connection
    renders exactly as before.
  - **P3 — an action you cannot do is not offered** (`permission_gate.go`).
    `allowsAction` withholds a menu item, toolbar button or context-menu entry
    only when the server answered "no" to *every* right that would permit it;
    the lists are alternatives, never a conjunction. A Properties page whose
    writes would be rejected opens read-only, with the right it needs at the
    top and **Close / Script Changes** in place of OK/Apply.
  - **P4 — from "denied" to "you need this"** (`permission_error.go`). The
    message table was measured against a real server rather than designed:
    eight statements run as a `db_datareader`, the multi-message pairs read
    through the driver's `All`. A refusal is rendered as *Access denied —
    Requires SELECT on msdb.dbo.sysjobservers*; an ambiguous message (Msg 5011,
    Msg 3701 — "does not have permission, the database does not exist, or…")
    is never called access denied, and a server whose messages are not in
    English shows its own sentence unchanged.
  - A database this login cannot open expands to a single *Access denied* node
    instead of nine folders that each fail separately
    (`explorer_databases.go`), and `DatabaseCapabilities.Permits` (gosmo) is
    the accessibility-aware test behind it.
- **`Script <object> as ▸` on every family the tree shows** (`scripting.go`) —
  one table of which verbs each `NodeType` offers and how each is generated,
  plus SSMS's three destinations (New Query Editor Window / File... /
  Clipboard). Sixteen node types script; CREATE, ALTER, DROP, DROP And CREATE
  and the SELECT/INSERT/UPDATE/DELETE/EXECUTE templates. An index adds REBUILD,
  REORGANIZE and UPDATE STATISTICS, generated by running gosmo's own methods
  under `WithScript` so they cannot drift from what the app executes; a
  statistics object gets Update Statistics, which opens the script rather than
  running it. The three hardcoded per-type Script items and `scriptObject` are
  gone.
- **Menu cascades** (`internal/tuikit/controls/menu_cascade.go`) — `MenuItem.
  Sub []MenuItem` makes an item open a submenu, shared by `MenuBar` and
  `ContextMenu`. The open chain stores a *path of indexes* rather than item
  lists, so every level is re-derived from the host's current menu each frame
  and a rebuilt menu cannot be navigated through a stale pointer.
- **New Index** (`new_index_dialog.go`, `new_index_pages.go`) — clustered and
  nonclustered (unique, included columns, filter, fill factor, PAD_INDEX,
  ONLINE, partition scheme), clustered and nonclustered columnstore, XML
  (primary and secondary with their secondary types) and spatial with
  tessellation scheme, bounding box and grid density. **New Statistics**
  (`new_statistics_dialog.go`) — ordered column list, filter, FULLSCAN or
  sample percentage, NORECOMPUTE, INCREMENTAL. Both offer Script Changes.
- **Four object families in the tree**: a database's new **Storage** folder
  (Partition Functions, Partition Schemes) and its Security folder's
  **Security Policies** and **Always Encrypted Keys** (Column Master Keys,
  Column Encryption Keys) — eleven node types with loaders, icons, filter
  entries, Delete, Properties, a Detail Browser view and Script entries. A
  security policy gets Enable/Disable, the disable confirmed first because it
  stops filtering and every protected row becomes visible.
- **New Column Master Key / New Column Encryption Key**
  (`new_column_master_key_dialog.go`, `new_column_encryption_key_dialog.go`) —
  both take the `0x…` blob SSMS or the PowerShell cmdlets print, because the
  enclave signature and the encrypted value are computed client-side from a
  private key that lives in a certificate store, a CSP/CNG provider or a Key
  Vault, none of which a portable no-CGO build can reach.
- **Missing-index banner on an execution plan**, with `m` or a click opening
  the `CREATE INDEX` script in a query window
  (`internal/showplan/missing_index.go`), and **`.sqlplan` open/save** — the
  same files SSMS reads and writes.
- **Log File Viewer: Recycle** (gosmo `CycleLog`, `EXEC sp_cycle_errorlog` /
  `EXEC msdb.dbo.sp_cycle_agent_errorlog`) and **a search the server runs**
  (`log_search_dialog.go`), rather than a filter over what was already read.
  `TreeView.OnActivate` gives Enter and double-click on a log leaf, falling
  back to expand/collapse when a node refuses.
- **Job Properties > Steps: Move Up / Move Down**, applied as a fourth pass
  after update/delete/add because a reorder names the step ids those three
  leave behind (`reorderedStepIDs`). gosmo gained `Job.InsertStep`,
  `JobStep.SetFlow`, `Job.MoveStep` and `Job.ReorderSteps`, plus the six
  `sp_add_jobstep` columns `JobStep` did not model — `proxy_id`,
  `additional_parameters`, `cmdexec_success_code`, `server`,
  `database_user_name`, `os_run_priority` — so a moved step keeps its proxy,
  run-as user and flags. `sp_delete_jobstep` silently resets any "go to step N"
  reference at or after the deleted step, which `ReorderSteps` repairs.
- **Start/Stop a job know its state** — both already fetched the job through
  `JobByNameContext`, so a Start on a running job is refused locally. The items
  stay ungreyed deliberately: a node's cached state is as old as the last
  folder load.
- **Delete a column, drop a table with cascade, Move to Schema, Rename a
  column.** gosmo gained `Table.DropColumn`, `Table.RenameColumn` and
  `Database.TransferObject`; `dialogs.ConfirmDialog` gained
  `ShowConfirmOption`, one checkbox above the separator leading the Tab cycle.
  The column-rename warning is asked *before* the rename, since `sp_rename`
  updates the column and nothing that names it.
- **Key Diagnostics can copy its log.** The hand-drawn list became a read-only
  `controls.Editor` with the gutter hidden, which buys mouse drag-selection,
  `Shift`+arrows, `Ctrl+A` and a scrollbar, plus a Copy button beside Close.
- **Peer credentials** (`app_peer_creds.go`, `db.ServerConn.SetPeerCredentials`)
  — a `Peer` connection used to reach every instance with the login the tree
  was registered with. A saved connection for that instance is preferred now,
  with the parent's own options retried once behind it, and an entry whose
  password this session cannot decrypt is never seeded.
- **Add Database to an availability group checks the full-backup
  prerequisite** — gosmo's `Server.DatabaseRecoveryStatuses` /
  `Database.RecoveryStatus` over `sys.database_recovery_status`, whose
  `LogBackupChainStarted` is what `ADD DATABASE` actually tests. msdb cannot
  answer it: a database whose backup history was deleted still qualifies.
- **New Endpoint's Script Changes groups by instance** — one collector per
  instance rather than one for the pipeline, with each statement labelled with
  the server it targets.

### Changed

- `gosmo` dependency updated `v0.0.9` → `v0.0.10` — the rest of the object
  families in the scripter (`ScriptTrigger`, `ScriptIndex`,
  `ScriptCheckConstraint`, `ScriptForeignKey`, `ScriptSequence`,
  `ScriptSynonym`, `ScriptSchema`, `ScriptUser`, `ScriptDatabaseRole`, a
  `ServerScripter` for `ScriptLogin`/`ScriptServerRole`, the DML templates and
  the `Database.Parameters` behind them, plus partition function/scheme,
  security policy and both Always Encrypted key scripters), `ScriptOptions.
  Verb` in place of the `ScriptDrops` bool, ten `…ByNameContext` finders,
  `ObjectFilter` and seven `…FilteredContext` listings,
  `Schema.ObjectCountsByType`, `CycleLog`, `Table.DropColumn`/`RenameColumn`,
  `Database.TransferObject`, `CreateColumnEncryptionKey`, the job-step
  insert/move/reorder family, `DataSpace` on `Table` and `Index`, the
  capability probe and `DatabaseCapabilities.Permits`.
- **Go 1.26 → 1.27; `tcell` v3.4.1 → v3.4.2.** `App.safego`/`safegoRepair` set
  their `what` string as a `runtime/pprof` label, so Go 1.27 heads the
  traceback of a panicking background goroutine with `{op: "loading the
  thing"}` instead of an anonymous func literal.
- **Connect is `F9`.** `Ctrl+Shift+O` works only where the terminal has a
  modern keyboard protocol, and `normalizeCtrlRune` (`app_events.go`) folds the
  chord back app-wide where it does.
- **The Object Explorer folder filter is pushed into gosmo's
  `…FilteredContext` listings.** The push-down is an optimisation and never the
  meaning of the filter: `filterChildren`/`filterObjects` still run over
  whatever comes back, so `nodeFilter.pushdown` either reproduces the client
  comparison exactly or refuses the whole filter, and a refusal reads the
  folder whole. gosmo's clause builder compares `LOWER(col) LIKE LOWER(@p)`
  (a bare LIKE follows the database collation) and escapes the pattern with
  `ESCAPE`, since `%`, `_` and `[` are legal in an identifier.
- **Ten lookups stopped fetching a listing to keep one row** — schema, index,
  statistic, foreign key, change-tracked table, partition function, partition
  scheme, security policy, column master key and column encryption key, each of
  which scanned every object of its kind on every Properties open and every
  Detail Browser selection. Every bulk listing stays; the finders were added
  additively.
- **Schema Properties' Object summary went from six listings to one query.**
  Five of the six were database-wide, and `ViewsContext`/
  `StoredProceduresContext` join `sys.sql_modules`, so counting six integers
  pulled every view and procedure's full definition across the wire. Now
  `Schema.ObjectCountsByType`.
- **`ExecutionPlan` gained `All []string`** — a batch of several statements
  produces several plan documents and `capturePlan` overwrote its field on each
  one. `XML` is still the last of them, so no existing caller changes
  behaviour. Settled live afterwards: across ten batch shapes under both
  `SHOWPLAN_XML` and `STATISTICS XML`, every showplan result set holds exactly
  one row.
- **Every `propPage` with a real Apply is now driven end to end by a test.**
  An audit found 52, of which 17 were covered; the rest landed in five phases
  over `internal/tui/fakedb_test.go`, which grew `db:` and `arg:` response
  scoping, `newFakeDialog`/`drainDialog` for the two pages that need an `App`,
  and `editText`/`editSelect`/`editRadio`/`toggleByName` — a row set with
  `SetValue` moves its dirty baseline and is skipped by Apply, so the first
  version of these tests proved nothing.
- **`internal/activity` went from 65% to 97% coverage.** What was uncovered was
  every DMV reader, where a scan into the wrong field yields a plausible number
  and no error at all.
- Comment pass across 65 files, keeping the "why" only where getting it wrong
  reintroduces a shipped bug.
- Repeated column-header literals hoisted to named vars — `database_props_
  files.go` spelled its seven-column header at four call sites,
  `securables_matrix.go` three headers at three to five each, and
  `{"Permission","State"}` appeared seventeen times. These pages read their
  grids back positionally, so a drifting header misaligns a column against its
  neighbour.
- Status-bar messages no longer end in a full stop (six literals across two
  files), matching every other `setStatus` in the app.
- `WriteAtomic`'s doc comment now records what the rename does *not* preserve
  (the original file's uid/gid), a decision rather than a fix: the alternative
  is new `runtime.GOOS` branching to serve a case goSSMS does not support.

### Fixed

- **Connect was unreachable by keyboard on every terminal.** tcell folds a
  Ctrl-modified rune into `KeyCtrlA..KeyCtrlZ` only when Ctrl is the *sole*
  modifier, so the `KeyCtrlO`+`ModShift` binding matched nothing on a modern
  keyboard protocol and arrived as plain `Ctrl+O` — File > Open — on a legacy
  one. `Ctrl+Shift+U` (Uppercase Selection) was dead the same way, and its unit
  test passed only because it synthesized an event tcell never produces. Found
  by injecting raw encodings with `tmux send-keys -H` and reading Key
  Diagnostics.
- **Server Properties > Processors wrote `affinity mask = 0`** on a login
  without VIEW SERVER STATE. `cpuCount` comes from the connect-time
  `sys.dm_os_sys_info` read, which that login is refused, so the affinity grid
  was built with zero rows while `affMask` still came from `sp_configure` —
  which reads fine. Apply compared an empty selection against a live mask,
  found them different, and unpinned the instance from its processors with
  nothing on screen having said so.
- **`Ctrl+X` in the Find dialog cut the query editor's text behind it.**
  `App.handleKey` consumes Ctrl+C/X/V centrally, before any dialog sees them,
  and `activeClipboardTarget` resolved the target from a switch naming three of
  thirty dialogs with a fall-through to the active panel. It now asks the
  frontmost dialog through `core.ClipboardHost` and never falls past it; a
  dialog with no text entry is deliberately not a host.
- **A paste followed focus to the next row.** `PropertySheet` answers
  `FocusedClipboardTarget` with itself and resolves the row on every call,
  which defeats `pasteInto`'s "is this still the target" guard — a paste aimed
  at Name and delivered after a Tab landed in Description. Fixed with
  `core.ClipboardTargetTokener`.
- **A click on a cell-cursor `DataGrid` moved the highlight without firing
  `OnSelectRow`.** Eleven pages wire a selection callback onto such a grid, and
  every one of them left its detail panel describing whatever row the keyboard
  had last selected.
- **`redrawGrid` lost the scroll position and any dragged column width.**
  Restoring the cell cursor alone is not enough: `SetSelectedCell` ends in
  `ensureVisible`, which scrolls from zero and lands the user's row against the
  bottom edge — Server Properties > Permissions moved the whole list on every
  toggle. `SetDataPreservingView` restores widths, then scroll, then selection.
- **A menu bar dropdown taller than the terminal lost its last items,
  silently.** `dropdownGeometry` never consulted the screen height: at 100×20,
  Edit's 21 items painted three of them past the bottom edge, invisible and
  unclickable, with the keyboard highlight walking onto them. `MenuBar` scrolls
  now (`scrollTop`, ▲/▼ marks, wheel support); `ContextMenu.geometry` is
  clamped instead, its upward shift having gone negative and taken the top rows
  off the other side. A context menu can be moved; a dropdown anchored under
  its header cannot.
- **The panel drop-down ran off the bottom of the screen.** `PanelManager.Draw`
  drew one row per panel with no bound, so with 24 panels on a 20-row terminal
  everything past Query 16 was undrawn and unreachable — including, often, the
  active panel. The list is capped and scrolls, its scrollbar is draggable
  (it was the only `core.DrawScrollbar` site in either repo with no
  `HandleScrollbarDrag`), and it takes the wheel and Page Up/Down.
- **Two mouse-latch defects in the same drop-down**: clicking an entry closed
  the list, leaving the held press to fall through to the query editor behind
  it, and `comboSbDragging` survived an `Escape` that closed the list mid-drag
  — so the next opening's first click anywhere on screen jumped the scroll.
- **`ShowConfirmOption`'s checkbox could be pressed once and never again.**
  `ConsumeOutsideClick` answers true for every event outside the rect,
  `ButtonNone` included, so the widget never saw the release and its
  `mouseDragging` latch outlived the gesture.
- **Key Diagnostics stopped recording after its own Copy button.** `copyAll`
  left the selection standing, `syncIfDirty` refuses to rebuild the editor
  while one is live, and a read-only editor rejects a non-movement key without
  clearing the selection — so the log froze on exactly the keys the dialog
  exists to decode.
- **Loaders read the live tree node from a background goroutine.**
  `App.loadChildren` passed the `*explorerNode` into `safegoRepair` and
  `fetchChildren` read `node.data` from it while the UI goroutine wrote it;
  `DetailBrowser.fetch` did the same. Both take a `nodeData` by value now, the
  way `deleteObject`, `runRename` and the Script generators already did.
- **The Status History ring was written from a loader goroutine.**
  `fetchChildren` calls `logStatus`, which appended to `d.lines` while the UI
  goroutine drew from it, and `Record` called `SetText` on the dialog's editor
  from the same goroutine. A mutex over the slice, and the editor rebuild moved
  onto the UI goroutine.
- **A scripted partitioned table came back unpartitioned.** `ScriptTable`
  emitted no `ON` clause, so the script ran clean and produced a
  single-partition heap on the target's default filegroup. gosmo carries
  `DataSpace` on `Table` and `Index` now, including the partitioning column,
  since `ON [scheme]([column])` is the whole clause.
- **`buildLoginScript` dropped the SID and mis-parsed its own output.**
  `Login.SID` was never scripted, so a login recreated on another server
  orphaned every database user mapped to it — the main reason to script a login
  at all. And `strings.Contains(stmt, " WITH ")` chose between opening and
  continuing a WITH list, so a login named `[svc WITH rights]` produced a
  statement that does not parse. Pinned live: the login is created, scripted,
  dropped and replayed, and the SIDs compared.
- **`FILEGROWTH = 0` was inexpressible**, so autogrowth could not be turned
  off from Database Properties > Files: `gosmo.FileModify`'s zero value means
  "leave this alone", and the value that disables growth is the same value.
- **`CREATE COLUMN MASTER KEY`'s enclave clause was never valid syntax.**
  `ENCLAVE_COMPUTATIONS = YES` raises Msg 102, a parse error TRY/CATCH cannot
  catch; the clause takes a signature computed client-side, which the bool
  signature could never supply. `CreateColumnMasterKeyWithSignature` replaces
  it.
- **The missing-index suggestion generated an index that could not seek.** The
  parser folded INEQUALITY columns in among the EQUALITY ones — every equality
  column has to come first — which reads harmlessly and silently costs the seek
  the suggestion existed to buy. `Inequality` is its own field now.
- **New Endpoint's Script Changes was live and wrong.** The shell's `OnScript`
  emitted every collected statement in one batch with nothing saying they
  belong to different instances; run whole against the connected one, the
  certificate imports fail and the endpoint GRANTs land on the wrong endpoint.
- **`newScopedConfigIntEditor` swallowed its parse error.**
  `sys.database_scoped_configurations.value` is a `sql_variant` and a readable
  secondary can hold `PRIMARY`, which rendered as `0` — a number the server
  never held, on the dirty baseline so Apply would not correct it either. The
  actual value now shows in a disabled row.
- **Three places the permission layer said something it had not measured**: Msg
  297's advice named VIEW SERVER STATE unconditionally, where a refused KILL or
  `sp_readerrorlog` raises it too; the Activity Monitor's gate read
  `selectedServerConn()` while the action resolves through `connOrFirst`, so
  with nothing selected the gate failed open onto a connection that refuses;
  and Recycle was gated in the Object Explorer and ungated on the Log File
  Viewer's own toolbar.
- **`deniedReadNote` asked for more privilege than the job needs.** Every read
  it covers is in the *performance* half SQL Server 2022 split VIEW SERVER
  STATE into, so it names both the wide right (for 2019 and earlier) and the
  narrow one. Server Properties > General also rendered physical memory with a
  bare `FormatInt` where Object Explorer Details uses `formatMB` — two
  spellings of one quantity read as two readings.
- **gosmo: `Capabilities.Allows` fails open on a database that cannot be
  opened.** Such a database answers `CapabilityUnknown` to every permission, so
  `Allows("BACKUP DATABASE")` returned true for one the login cannot connect
  to. `DatabaseCapabilities.Permits` is the accessibility-aware test, added
  additively; goSSMS's private `dbAllows` workaround is gone.
- **gosmo: a scripted sequence restart moved the handle anyway.**
  `Sequence.RestartContext` assigned `CurrentValue` straight after an ALTER
  that `WithScript` only captured, so the handle claimed a value the server
  would not hand out for another five thousand calls.
- **gosmo: `CreateDatabaseMirroringEndpointContext` returned `(nil, nil)` under
  `WithScript`**, alone among the scripted creates, so `ensureEndpoint` had to
  bail out of the rest of the pipeline.

## [0.0.7] - 2026-08-19

### Added

- **Always On Availability Groups**, built in seven phases and end to end —
  reading a topology, editing it, watching it, and creating one.
  - **Object Explorer** grows an `Always On High Availability` folder between
    Server Objects and SQL Server Agent, with nine node types over
    availability groups, replicas, availability databases and listeners
    (`explorer_alwayson.go`). The folder is listed unconditionally and reports
    "Always On is not enabled on this instance" on expansion rather than being
    hidden behind a query. Labels distinguish a group with no visible primary
    as `(Not synchronizing)` rather than `(Secondary)`, and a database shows
    every distinct state across replicas instead of collapsing them.
  - **Everything follows the primary.** `sys.availability_groups` and
    `sys.availability_replicas` are cluster-wide, but the `sys.dm_hadr_*` DMVs
    describe only what the connected instance can see, so a topology read from
    a secondary comes back with every peer's role, connection state and health
    blank. `db.ServerConn.Peer` (`internal/db/peer.go`) opens and caches a
    connection to another instance with the same credentials, and every loader
    re-reads through it when the local instance is not the primary; the tree
    says so with a `(read from primary <host>)` note. An unreachable primary
    degrades to the partial local view with a `NodeError` naming the host,
    rather than failing.
  - **AG Properties** — General, Backup Preferences and Read-Only Routing over
    the existing `PropDialog` shell. Everything routes through `agOnPrimary`,
    which errors rather than degrades, since `ALTER AVAILABILITY GROUP` is
    rejected on a secondary. Apply re-resolves the primary and diffs against
    the values captured at load, so a concurrent change to a replica this user
    never touched is not written back. Read-only routing is written in three
    phases (`planAGRoutingOps`) — URLs being set, then every list, then URLs
    being cleared — because the server refuses a list naming a replica with no
    URL and refuses to clear a URL a list still names.
  - **AG Dashboard** — a panel rather than a dialog, in two modes: one group
    (header rollup, replica grid, per-database grid) or every group from the
    Always On root. The two numbers worth having are the two SQL Server does
    not report: estimated data loss, measured against the *primary's* row for
    the same database, and estimated recovery time from redo queue over redo
    rate. Both render an em dash when unknown and never 0s — "no data loss"
    and "we cannot tell" are opposite answers. Refresh rate is `+`/`-` over
    5/10/30/60 s, matching the Activity Monitor's keys.
  - **Operations** (`alwayson_menu.go`) — add and remove a database, join and
    unjoin a secondary's own copy, suspend and resume data movement, add and
    remove a replica, add, modify and remove a listener, fail over (planned or
    forced with data loss), and drop a group. Where an operation runs is part
    of what it means: membership changes go to the primary, suspend and resume
    to the tree's own connection, and the confirmation says which instance the
    user is about to affect. Failover lives on the replica being promoted.
    `agFailoverRefusal` explains rather than sending a statement the cluster
    type forbids, naming Pacemaker's `crm resource move` for an EXTERNAL
    group.
  - **New Availability Group** — four statements across three instances:
    CREATE on the connected instance, then JOIN and (for automatic seeding)
    GRANT CREATE ANY DATABASE run by each secondary against itself through
    `Peer`. `annotateScript` labels every statement in Script Changes with the
    instance it targets, since running the set whole against the primary would
    join the primary to its own group. A group created whose secondary cannot
    join reports exactly that rather than a plain failure.
  - **Add Replica**, **Add Database**, **Add Listener** and **Listener
    Properties**. Add Replica reads the endpoint URL through a Connect button
    rather than at apply time, and replaces what was typed with the instance's
    own `@@SERVERNAME`; the URL stays editable afterwards for a topology where
    only the FQDN resolves, with `validateEndpointURL` behind it. A listener
    takes a list of addresses, and the typed IP/mask counts toward the spec
    without pressing Add Address.
  - **New Database Mirroring Endpoint** — creates the certificates, logins,
    users, endpoints and grants across every replica, exchanging **public**
    certificates over connections gossms already has (`CERTENCODED` /
    `CREATE CERTIFICATE ... FROM BINARY`) instead of the documented
    BACKUP-to-file-and-copy route. No private key is read, transmitted or
    written. Every step is skipped when what it creates already exists, so a
    half-configured pair is completed rather than refused.
  - A database in an availability group carries its state in the **Databases
    folder** label. The state shown is the local replica's alone.
- **Log File Viewer** (`log_viewer.go`) — SQL Server and SQL Agent error logs,
  current or archived, over a grid of Date/Source/Message with a details pane
  under a draggable divider, a filter field, Refresh and Export. Rows are
  newest first with the direction marked in the header, and the sort is stable
  so a startup sequence keeps the order the log wrote it in. Object Explorer
  grows a **Management** folder (SQL Server Logs) and **Error Logs** under SQL
  Server Agent.
- **Object Explorer folder filter** — SSMS's Filter Settings on a folder node,
  over Name, Schema, Creation Date and Is Memory Optimized. Filtering runs in
  `fetchChildren` on whatever the loader returned, so a filter survives
  Refresh, collapse/expand and reconnect without any loader knowing it exists.
  Sub-folders and error nodes are never filtered out, and the `(filtered)`
  suffix is rendered rather than stored. `App.savedFilters`, keyed by
  connection/database/schema/table/node type, keeps a filter across a
  disconnect for the session; nothing is written to disk.
- **General Delete and Rename** (`explorer_object_ops.go`) — one table of what
  each verb means per node type, so a node type absent from it offers neither.
  Confirmations scale with the blast radius: a plain Yes/No for one object,
  the retype-the-name dialog for a database. Renaming a database offers the

- **Result sets cost far less to keep.** A new `cellArena`

### Fixed

- **`Ctrl+V` did nothing in the query editor** whenever the results pane
  happened to be showing Messages, the execution plan, or Results To Text —
  any `PRINT`, `SET`, error, or non-`SELECT` batch left it there. Paste was
  routed by which tab was visible, ignoring which half of the panel had
  keyboard focus, and every one of those views is read-only, so the paste
  silently went nowhere.
- **A terminal paste was replayed as typing.** tcell brackets a paste but
  still delivers its content as ordinary key events, and nothing handled the
  markers — so each pasted newline arrived as `Enter`, and with the
  IntelliSense popup open it committed the selected candidate instead.
  Pasting `objects\nWHERE type = 'U'` over `sys.` produced
  `sys.objectsWHERE type = 'U'`. A paste is now applied as one edit and one
  undo step, and anything that isn't a rune, newline, or tab is dropped
  rather than acted on.
- **Wide characters were being eaten** by the editor and every input field.
  Recorded as a cursor-position bug, it was worse: typing `世界ab` into the
  Connect dialog's Server field rendered `世ab`, and 32 ideographs in a
  wrap-mode field collapsed onto one row of 16 glyphs. Every second rune was
  overwritten by the previous one's continuation cell.
- **A `GO` inside a block comment or string literal started a new batch**
  for IntelliSense scoping, so `SELECT * FROM dbo.Patients p /* GO */ WHERE
  p.` offered no completions. Batch detection now falls out of the lexer's
  own state machine, which covers comments, string literals, and bracketed
  identifiers in one rule.
- **A `/*` inside a `--` comment or a string literal** left the SQL
  highlighter believing it was inside a block comment for the rest of the
  document.
- **A scrollbar drag in a Properties dialog could fire Script Changes** —
  the form's scrollbar column and `[ Script Changes ]`'s last column are the
  same column, and the button row was hit-tested before the form.
- **Script Changes on the create dialogs failed with "not found."** gosmo's
  Agent `Create*` methods ended with a read-back that went to a real server
  under scripting mode, looking for an object whose `sp_add_*` had merely
  been collected. Fixed in both repos; the dialogs now use name-only
  handles.
- **Date and time columns ignored their declared scale** — `time(0)`
  rendered as `.0000000`.
- **A create dialog re-ran a successful create on a second Apply**, coming
  back with the server's "already exists"; a fast page switch could also
  start a second prefetch and rebuild every form from it.
- **The status bar stuck on "Executing query…" forever** after a query
  panel was closed mid-execution.
- **A modal dialog's mouse latch survived into its next showing**, freezing
  the first click of every reopened dialog.
- **A press on the Object Explorer's scrollbar or empty space started a
  drag** of whatever node happened to be selected; drag arming now asks what
  the press actually landed on (`TreeView.NodeIDAt`).
- **The "Show Value" popup was dismissed by any stray click** while reading
  a long value, and could be left stranded over stale text when new results
  arrived — it now closes only on Escape or its own Close button, and is
  closed explicitly when the grid's data is replaced.
- **`Form.scroll` was never re-clamped on resize**, and
  `DetailBrowser.PurgeConn` left a disconnected connection's rows on screen.
- Long messages could overflow a dialog's height on a short terminal,
  drawing over the separator and button row.
