Source: open-threads § Command line, last-but-one bullet. A Reader/User member
gets Access denied on Agent ▸ Operators and on Job Properties ▸ Alerts /
Notifications.

   (as F1 did for jobs/steps/history/schedules) — `msdb.dbo.sp_help_operator`
   and `msdb.dbo.sp_get_job_alerts`, both granted to SQLAgentUserRole. Keep
   the `sysoperators` SELECT for sysadmin/OperatorRole if it returns more

   them, but make the refusal a typed permission error, not a generic one.
3. gossms: hide the Alerts folder for a login without OperatorRole (as SSMS
   does) instead of the Access-denied placeholder; Operators and Job
   Properties ▸ Alerts/Notifications read through the new route.

   job Alerts page lists, Alerts folder absent. Run `TestLiveVersionSweep` on 13.

Files: gosmo `agent_operator.go`, `agent_alert.go`; gossms
`internal/tui/agent_explorer.go`, `agent_job_props_alerts.go`.

Source: open-threads § Command line (D10). `audit.jsonl` grows forever.

   exceeds a cap (e.g. 10 MiB), rename to `audit.jsonl.1` (replacing any

## Priority 2 — gosmo correctness

### K4 — `ScriptDatabase` omits a leftover TDE key silently without VIEW SERVER STATE

Source: gosmo OPEN-THREADS § ScriptDatabase, TDE bullet. For an *unencrypted*
database the DMV refusal is silent, so a key left behind by `SET ENCRYPTION
OFF` vanishes from the script with no comment.

1. `scripter.go` (~line 314/781): when the DMV is refused, emit a comment for
   unencrypted databases too ("reading a leftover encryption key needs VIEW
   SERVER STATE: not checked").
2. Unit test for both branches; live replay test as a login without VIEW
   SERVER STATE on 17.

### K5 — Scoped configuration with a string value becomes a comment

Source: gosmo OPEN-THREADS § ScriptDatabase, scoped configurations bullet.
`scopedConfigValue` (`scripter.go:845`) handles numbers, 0/1, bare keywords;
anything else (e.g. `LEDGER_DIGEST_STORAGE_ENDPOINT` URL) gets a comment.

1. For an `nvarchar`/`varchar` base type that is not a bare keyword, emit a
   quoted literal (`tsql.QuoteString`) — `SET LEDGER_DIGEST_STORAGE_ENDPOINT
   = N'…'` is documented syntax.
2. Unit-test only (no Azure SQL Database); say so in OPEN-THREADS.

### K6 — `Sequence.NextValue` returns int64 (breaking)

Source: gosmo OPEN-THREADS § `Sequence.NextValue`. Fails on a `decimal(38,0)`
sequence past bigint. No gossms caller.

1. Change to `(string, error)`, scanning the value as decimal digits like the
   other sequence fields. Note under CHANGELOG "Breaking" at release time.
2. Live: a `decimal(38,0)` sequence started at 10^20 on 17.
