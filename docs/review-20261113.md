## Bugs

### R1 — The safety classifier calls six statements `read` behind IF/ELSE/WHILE/BEGIN (probed) — DONE 2026-11-13

`internal/cli/safety/classify.go`. Statements whose verb is neither a
`sqltext` statement leader nor a `floorWords` entry are classified only when
they open a statement. Nested, they inherit the enclosing leader's `read`:

| Script | Got | Should be |
|---|---|---|
| `IF 1=1 SETUSER 'x'` | read | admin |
| `IF 1=1 SEND ON CONVERSATION @h ('x')` | read | write |
| `IF 1=1 MOVE CONVERSATION @a TO @b` | read | write |
| `IF 1=1 ADD SIGNATURE TO dbo.p BY CERTIFICATE c` | read | ddl |
| `GET CONVERSATION GROUP`, `END CONVERSATION` behind IF | read | write |

The same holds after `ELSE`, `WHILE …`, and inside `BEGIN … END` / `BEGIN TRY`.
`Classify`'s doc says it fails closed; here it does not, so `query run` at the
default `--allow read` sends them.

Fix: one table of verb (or phrase) → class that both `leaderRule` and `floor`
read, so a verb cannot be in one and missing from the other. The nested forms
match as phrases, as `NEXT VALUE FOR` already does (`SEND ON CONVERSATION`,
`MOVE CONVERSATION`, `GET CONVERSATION`, `END CONVERSATION`,
`ADD [COUNTER] SIGNATURE`), so a column named `send` or `add` stays read;
`SETUSER` matches bare. Add an invariant test: for every leader the table
gives a class above read, `IF 1=1 <stmt>`, `ELSE <stmt>` and
`BEGIN <stmt> END` classify at least that high. Update `docs/cli.md` § Safety.

### R2 — `data import` rejects a CSV that starts with a BOM and a quoted header (probed) — DONE 2026-11-13

`internal/cli/cmd/data_import_file.go` strips the BOM from the first *cell*
after `export.RecordReader` has parsed the record. A file beginning
`﻿"Order Date",x` fails earlier, inside the reader, with `line 1: a quote
(") in an unquoted field`. Excel writes exactly this for a header that needs
quoting.

Fix: strip the mark from the byte stream in `openImportFile`, before any
format's reader sees it (peek three bytes on a `bufio.Reader`), and drop the
cell-level `TrimPrefix`. The JSONL reader gets the same stream, so check it
with a BOM-prefixed valid file while there (not verified either way).

Done: `skipUTF8BOM` strips it from the stream in `openImportFile`. The JSONL
reader was broken too (a BOM-prefixed `_resultSet` line was "not a
_resultSet line"); `TestDataImportByteOrderMark` covers csv, tsv and jsonl,
and both were loaded live on win10cli.

### R3 — `GO 0` drops its batch without a message (probed, low)

`sqltext.SplitBatches` returns `Count: 0` and `query.runScript` loops zero
times; the "Batch execution completed n times." notice is only for `Count >
1`. The batch is silently not run. Confirm what SSMS does on a live editor,
then either print the notice for 0 or match SSMS. (`GO 99999999999999999999`
saturating to `math.MaxInt` is deliberate in `go_separator.go` and stays.)

## Inconsistencies

### R4 — Backup pre-flight rules differ between the TUI and the command line

`internal/tui/backup_dialog.go` (`backupTypeBlocks`) refuses a differential or
log backup of `master` (Msg 3024/4212), a differential with no base (3035) and
a log backup with no chain (4214), from live-probed facts.
`internal/cli/cmd/maint_backup.go` knows only tempdb, snapshots and SIMPLE
recovery, so `maint backup --type diff` on a database with no full backup goes
to the server and comes back as a hinted server error instead of exit 2.

These are SQL Server facts, not UI: put the decision in gosmo as a pure
function over `Database` and its backup status that returns a typed reason
(none, master-full-only, simple-recovery, no-differential-base,
no-log-chain, tempdb, snapshot). The TUI keeps its hint wording, the CLI its
exit codes and hints; both switch on the reason.

### R5 — Two script-file decoders with different rules — DONE 2026-11-13

`decodeScript` (`internal/cli/cmd/query_input.go`) and `decodeTextFile`
(`internal/tui/text_encoding.go`) each detect the BOM and decode UTF-16 by
hand. The CLI refuses an unpaired surrogate; the TUI substitutes U+FFFD and
reports `lossy`. Move the decoding to one stdlib-only leaf package returning
text, encoding and `lossy`; the CLI refuses on `lossy`, the TUI warns as now.
R2's BOM strip can use the same detection.

Done: `internal/textenc` (`Decode`, `Encode`, `SkipUTF8BOM`; stdlib only).
`readSQL` refuses on lossy and now names UTF-16 when the mark said so; the
TUI's `decodeTextFile`/`encodeTextFile` add only line endings on top;
data import's stream strip and a third copy in `showplan`'s `.sqlplan`
reader moved onto it too. Driven live: `query run -i` of a UTF-16LE file on
win10cli, latin-1 and lone-surrogate files refused; File > Open → edit →
Save of a UTF-16LE file stays UTF-16LE, a lossy one opens with the warning.

### R6 — gosmo: `UPDATE STATISTICS` has two forms whose zero means opposite things — DONE 2026-11-13

`Statistic.Update(ctx, samplePct)`, `Table.UpdateAllStatistics`,
`View.UpdateAllStatistics` and `Index.UpdateStatistics` take a percentage
where 0 is FULLSCAN. `Statistic.UpdateWith`, `Table.UpdateStatisticsWith` and
`View.UpdateStatisticsWith` take `StatisticsUpdateOptions`, where the zero
value sends no clause (the server's default sample). This is the
`Foo`/`FooContext` pair the one-form rule in `~/go/gosmo/CLAUDE.md` removed,
with a trap added.

Fix (breaking): keep the options form only, under the plain names —
`Statistic.Update(ctx, opts)`, `Table.UpdateStatistics(ctx, opts)`,
`View.UpdateStatistics(ctx, opts)`, `Index.UpdateStatistics(ctx, opts)`.
`Database.UpdateStatistics(ctx, resample)` is `sp_updatestats` and stays.
gossms has few callers; a zero-percent caller becomes `FullScan: true`.

Done: `Statistic.Update`, `Index.UpdateStatistics`, `Table.UpdateStatistics`
and `View.UpdateStatistics` take `StatisticsUpdateOptions`; `UpdateWith`,
`UpdateStatisticsWith`, `UpdateAllStatistics` and `sampleClause` are gone.
`Index.UpdateStatistics`'s zero now sends no WITH (offline cases for both
that and `FullScan`). gossms's TUI and Script As callers pass `FullScan:
true`, so their statement is unchanged. Live: the touched gosmo live tests
on win10cli; `maint update-stats` dry runs (default, fullscan, one
statistic sampled).

### R7 — gosmo: `Enable`, `Disable` and `SetEnabled` on fifteen types — DONE 2026-11-13

Alert, Job, Operator, Schedule, Login, Trigger, DatabaseTrigger,
ServerTrigger, PlanGuide, SecurityPolicy, ServerAudit, both audit
specifications and FullTextIndex each carry all three; `SetEnabled` only
dispatches. gossms calls `SetEnabled` 14 times, `Disable` 6, `Enable` 2.

**Decision needed.** Recommended: keep `SetEnabled(ctx, on)` where the two
directions are symmetric (what a toggle calls) and delete the pair; keep
`Enable`/`Disable` only where they are not one switch (`Index`: Enable is a
rebuild; `ResourceGovernor`). The alternative — keep the pair, delete
`SetEnabled` — reads closer to T-SQL but turns 14 call sites into if/else.

Done (decided: keep `SetEnabled`): the pair is gone from the fourteen types
that had all three (the count above was one high); `SetEnabled` now holds
each body. `Index` and `ResourceGovernor` keep `Enable`/`Disable`.
`set_enabled_test.go` now fails if a switch-like type grows the pair back;
the four stale `Login`/`Job` `sweepSkip` entries are gone, and comments,
`ARCHITECTURE.md` and the class diagrams use the one form. gossms changed
three call sites (full-text Enable/Disable, New Login's Disabled status).
Live: the 14 gosmo live tests that toggle state, on win10cli; in the built
binary, full-text Disable → Enable on a throwaway table and New Login with
Disabled (`is_disabled` 1; Script Changes shows `ALTER LOGIN … DISABLE`).

### R8 — gosmo: role membership has a second, delegate-only form — DONE 2026-11-13

`Login.AddToServerRole`/`RemoveFromServerRole` and
`User.AddToRole`/`RemoveFromRole` are one-line delegates to
`ServerRole.AddMember`/`DatabaseRole.AddMember` and their `RemoveMember`.
gossms calls `AddToServerRole` twice and the `User` pair never. Delete the
four (breaking); callers use the role's method.

Done: the four are deleted; their offline cases moved onto
`ServerRole.AddMember`/`RemoveMember`, which had no other statement test.
Login Properties and New Login go through `ServerRoleRef(name)`.

### R9 — gosmo: system-procedure writes interpolate what they could bind (low)

`AddExtendedProperty`/`SetExtendedProperty`/`DropExtendedProperty`,
`sp_addumpdevice`/`sp_dropdevice` and `sp_configure` escape values into the
statement text, while `sp_rename` and the Agent procedures bind `@p1`. The
escaping is correct; the convention in `~/go/gosmo/CLAUDE.md` is "prefer a
query parameter where accepted", and `bindScriptArgs` already renders bound
arguments for a captured script. Convert them; the script-capture goldens
show whether the rendered text changes.

### R10 — gosmo: a bound `time.Time` would script a literal `datetime` rejects (latent, low)

`scriptLiteral` renders `time.Time` with up to seven fractional digits. That
text fails conversion to a `datetime` parameter when a captured script is run
by hand. No write binds a `time.Time` today, and Database Mail formats its own
three-digit literal (`mailDateLiteral`) for this reason. Either make
`scriptLiteral` refuse `time.Time` like any other unsupported type, or give it
one documented form and move `mailDateLiteral` onto it.
